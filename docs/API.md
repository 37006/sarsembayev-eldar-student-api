# Student API

Base URL: `http://127.0.0.1:8083/api/sarsembayev-eldar/students`

| Method | Path | Expected result |
|---|---|---|
| POST | base URL | 201 Created, generated ID, Location header |
| GET | base URL | 200 OK, array ordered by ID |
| GET | /{id} | 200 OK, or 404 for an unknown ID |
| PUT | /{id} | 200 OK, updated record; all four fields required |
| DELETE | /{id} | 204 No Content, or 404 for an unknown ID |

Request fields: `firstName` and `lastName` (nonblank, up to 80 characters), `email` (valid, up to 254), and `groupName` (nonblank, up to 30). Emails are stored in lower case and must be unique. Invalid input returns 400; a duplicate email returns 409. Error bodies use Spring ProblemDetail. IDs are generated by the database.

All four fields must be JSON strings. Numeric and boolean values are rejected rather than converted to text. Leading and trailing Unicode whitespace is removed, and email case is normalized, before validation and length checks. A value consisting only of whitespace is invalid. An invalid PUT leaves the stored record unchanged. An unexpected database integrity failure returns a generic 500 instead of incorrectly claiming that the email already exists.

```bash
BASE=http://127.0.0.1:8083/api/sarsembayev-eldar/students
curl -i -X POST "$BASE" -H 'Content-Type: application/json' --data '{"firstName":"Eldar","lastName":"Sarsembayev","email":"37006@iitu.edu.kz","groupName":"IT2-2301"}'
curl -i "$BASE"
# Replace 1 below with the ID returned by POST.
curl -i "$BASE/1"
curl -i -X PUT "$BASE/1" -H 'Content-Type: application/json' --data '{"firstName":"Eldar","lastName":"Sarsembayev","email":"37006@iitu.edu.kz","groupName":"IT2-2301-UPDATED"}'
curl -i -X DELETE "$BASE/1"
curl -i "$BASE/999999999"
```

The records above are individual test data, not a production student register. `python3 scripts/api_check.py` performs the complete sequence with a unique test email and removes its own test record. The separate persistence demonstration retains one identifiable sample.
